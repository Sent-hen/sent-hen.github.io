---
title: "What's left when the typing is automated"
date: 2026-10-15
---

My interest in systems thinking started with one question: what's left when writing code by hand gets automated?

I made a few guesses back then, and they're coming true. Tools like Claude and GPT, what most people just call AI, are amazing mimicry artists. They can do a lot of great things, and typing out code by hand is turning into something you only do in an emergency.

The best answer I've found comes from 1985. In "Programming as Theory Building," Peter Naur argues that a program isn't its source code. The real program is the theory in the developers' heads: what the system does, why it does it that way, and how it should change. The code is just a lossy copy of that theory. Christian Ekrem's [write-up of the essay](https://cekrem.github.io/posts/programming-as-theory-building-naur/) puts the AI angle bluntly: generated code is "nobody's theory." It can pass the tests without anyone understanding the trade-offs behind it. It copies like a parrot, or blends in like a chameleon.

So the bottleneck is shifting away from writing code and toward holding the theory: how good the decisions are, and how clearly the whole architecture is thought through, drawbacks included.

That's what pulled me into systems, since a theory of a program is really a model of a system. Reading Donella Meadows's *Thinking in Systems*, I started to see a revolution inside the AI revolution: the sciences are running into the limits of reductionism, and that's bringing holism and systems thinking back into the light. None of these ideas are new to the scientific community; they're just coming back around. It all feels very Hegelian: thesis, antithesis, synthesis, with dualities like order and chaos, or creation and destruction, playing out again.

If the parts are getting cheap to make, the value is in the theory of how they fit together.
